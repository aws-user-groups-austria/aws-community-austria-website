# public/live

This folder holds the built meetup web player and the event files it reads.
GitHub Pages serves it at `/live/`, next to the site but outside the React
router.

| Path | What |
|------|------|
| `index.html`, `assets/` | The built web player from `meetup-stream-templates/web-player/dist/` in the meetup stream workspace: the script bundle, and `assets/logos/` with the community logos |
| `fonts/` | Inter, served to the player's scenes (from the same build) |
| `events/<id>.json` | One `event.json` per meetup, copied from `meetup-event-vienna/events/<id>/event.json` |
| `events/<id>/assets/` | That meetup's speaker photos and sponsor logos, when it has any, copied from `meetup-event-vienna/events/<id>/assets/` |
| `events/index.json` | Each synced meetup's Meetup link and id; the site shows "Open the live stream" on every event card whose link is listed here |
| `events/README.md` | One line, written by the sync |
| `README.md` | This file, kept when the folder is refreshed |

Everything except this README is generated by `npm run live:sync`, so the
subfolders (`assets/`, `assets/logos/`, `fonts/`, `events/`) carry no README
of their own, apart from the one line the sync writes into `events/`. The
player build's own `events/` folder (its local copies for development) is
not copied; the event files here always come from `meetup-event-vienna`.

## Refresh it

Build the web player first, in the `meetup-stream-templates` folder of the
meetup stream workspace:

```bash
make player-build
```

Then run this from the website root:

```bash
npm run live:sync
```

The workspace is expected at `../aws-community-meetup-stream-all`. Point to a
different one with `MEETUP_STREAM_DIR`:

```bash
MEETUP_STREAM_DIR=/path/to/aws-community-meetup-stream-all npm run live:sync
```

Everything in this folder except this README is replaced on every sync. Commit
the result so GitHub Pages serves it.

## Open it

```text
/live/?event=2026-10-20-aws-meetup-vienna-53
```

The player resolves an id to `./events/<id>.json`.
